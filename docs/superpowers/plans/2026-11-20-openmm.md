# openmm 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `ghcr.io/brineylab/toolshed/openmm:1.0.0`: OpenMM with an `openmm` wrapper (`relax`, `md`), glycan support, and a documented AIMNet2 ML/MM script, tested on a GPU with no network.

**Architecture:** One image: a pinned micromamba environment from conda-forge on an NVIDIA CUDA 12 base, AIMNet2 weights baked at a fixed path, and one wrapper program, `bin/openmm`, that prepares input (PDBFixer for protein atoms, a CCD→GLYCAM renaming for glycans, OpenMM for hydrogens) and runs two fixed protocols. ML/MM is a script in the skill, not a verb. The test (`test/run.sh` + `test/check.py`) runs every documented command on Boltz-2 fixtures and checks known answers.

**Tech Stack:** OpenMM 8.6.1, PDBFixer 1.12, openmm-ml 1.8, aimnet 0.2.6, Python 3.12, micromamba, podman/pyxis.

**Spec:** `docs/superpowers/specs/2026-11-20-openmm-design.md` (approved 2026-11-20). Read it first; this plan argues from it. Also read `AGENTS.md`, `CONTRIBUTING.md`, and `tools/tmol/` (the nearest sibling: a library with a shed wrapper, a library-way script in its skill, and a `check.py` with pinned known answers).

## Global Constraints

- Every rule in `AGENTS.md` "Rules a tool must keep"; the Containerfile ends with `COPY test /toolshed/test`.
- Base image and every package pinned to an exact version; micromamba binary pinned by version and sha256.
- `ENV NVIDIA_VISIBLE_DEVICES=all NVIDIA_DRIVER_CAPABILITIES=compute,utility HF_HUB_OFFLINE=1 AIMNET_CACHE_DIR=/opt/openmm/models/aimnet2`.
- Wrapper shebang `#!/usr/bin/env -S python3 -I`; every library-way example runs `python3 -I`.
- No run-time network: the test passes under `podman run --network none`. Nothing calls PDBFixer's hydrogen step (it downloads from RCSB).
- Force field, both verbs and the ML/MM script: `ForceField('amber14-all.xml', 'amber14/tip3pfb.xml', 'amber14/GLYCAM_06j-1.xml')`; hydrogens via `Modeller.loadHydrogenDefinitions('glycam-hydrogens.xml')` then `addHydrogens(forcefield, pH=7.0)`.
- Platform: CUDA with `{"Precision": "mixed"}` when available, else CPU.
- `md` protocol: orthorhombic box, 1.0 nm padding, neutralize, 0.15 M NaCl; PME, 1.0 nm cutoff, `ewaldErrorTolerance=5e-4`; `hydrogenMass=1.5*amu`, `constraints=HBonds`, 4 fs; `LangevinMiddleIntegrator(300*kelvin, 1/picosecond, 0.004*picoseconds)`; `MonteCarloBarostat(1*bar, 300*kelvin)`; minimize, 100 ps NVT, 1 ns NPT with heavy-atom restraints released over the NPT stage, then `--ns` ns NPT production; a frame and a `state.xml` every 100 ps (25,000 steps).
- Outputs carry GLYCAM residue and atom names; preparation accepts GLYCAM-named input unchanged.
- Supported CCD sugars: `NAG`, `NDG`, `BMA`, `MAN`, `FUC`, `FUL`, `GAL`, `GLA`, `SIA`, `SLB`; attachments Asn→`NLN`, Ser→`OLS`, Thr→`OLT`. Any other non-standard residue without a template stops the run naming residue and chain.
- ML/MM: AIMNet2, loaded with `MLPotential('aimnet', modelPath=<file under /opt/openmm/models/aimnet2/>)`, never from `~/.cache`.
- The test fits one GPU and 30 minutes and writes only under `/tmp`.
- Commit messages are one sentence stating the behavior, ending with the session's Co-Authored-By line. Pushing a candidate and opening the PR publish under the human's name: ask them first.

## Review Focus

1. **Two glycosylation sites, one a lone terminal NAG.** A person expects each site named by its own linkages (`0YB` for the lone one, `4YB`/`VMB`/`0MA` in the core). Pinned by the fixture in Task 3 and checked in Task 4.
2. **A rerun of `md` into an `out/` that holds a different input's run.** Expected: exit nonzero, saying so, nothing overwritten. Test in Task 5.
3. **A crash between writing a frame and saving `state.xml`** (one frame and log row past the state). Expected: the resume cuts them and the trajectory has no duplicate times. Test in Task 5 (append a frame and row by hand, then resume).
4. **`md` rerun with a smaller `--ns` than already run.** Expected: exit 0, a message on stderr, files byte-identical. Test in Task 5.
5. **`relax` on a directory where one file has an unsupported sugar, or two files share a stem (`a.pdb`, `a.cif`).** Expected: exit nonzero naming the file (and the residue), before writing anything for the clash case. Test in Task 4.

### Task 4: Preparation and `openmm relax`

**Files:**
- Create: `tools/openmm/bin/openmm`, `tools/openmm/test/run.sh`, `tools/openmm/test/check.py`
- Modify: `tools/openmm/Containerfile` (copy the wrapper, `openmm --help` smoke check)

**Interfaces:**
- Produces, in `bin/openmm`:
  - `forcefield() -> ForceField` (the triple in Global Constraints)
  - `select_platform() -> tuple[Platform, dict]`
  - `prepare(path: Path) -> Modeller`: load PDB/mmCIF (`PDBFile`/`PDBxFile`, which keeps `struct_conn` bonds); PDBFixer adds missing heavy atoms to standard residues only (no missing residues, no heterogen removal, never its hydrogen step); `glycam_rename`; add any inferred linkage bonds; hydrogens; then verify every residue matches a template (`forcefield().createSystem` succeeds) and every input glycan residue is present with hydrogens. Raises `SystemExit("<file>: unsupported residue <NAME> chain <C> <num>")` on a residue it cannot place.
  - `glycam_rename(topology: Topology, positions) -> None`: renames CCD sugars and their attachment residues in place, residue and atom names; leaves GLYCAM-named residues untouched. Linkage positions come from bonds; when a sugar's anomeric carbon has no bond to an O or Asn ND2, infer it by distance (cutoff the builder's, stated in a comment). The GLYCAM letter for each substitution pattern and the atom-name map come from GLYCAM's naming guide (https://glycam.org/docs/forcefield/glycam-naming-2/index.html), and every produced residue name must exist as a template in OpenMM's `amber14/GLYCAM_06j-1.xml`.
  - `openmm relax <in> <out>`: as spec §4. Writes `<out>/<stem>.<pdb|cif>` and `<out>/relax.tsv` with header `name\tenergy_before\tenergy_after\theavy_atom_rmsd`. Checks stem collisions before writing anything.
- First check whether GBn2 parameterizes GLYCAM atoms (`ForceField(..., 'implicit/gbn2.xml').createSystem` on the prepared fixture). If it does not, glycosylated inputs relax in vacuum with the same restraints; record which in a comment and in the skill (Task 7).

- [ ] **Step 1: Write the failing test.** `run.sh` (bash, `set -euo pipefail`, temp dir under `/tmp`, `trap` cleanup, as tmol's) copies `complex.cif` and `1UBQ.pdb` into `$T/in`, runs `openmm relax "$T/in" "$T/relax"`; writes `$T/nobonds/complex.cif` (the fixture with the `_struct_conn` loop removed, by a short inline `python3 -I` text edit) and relaxes it to `$T/relax-nobonds`; writes `$T/bad/complex.cif` with the first `MAN` renamed `GLC` and asserts `openmm relax` exits nonzero with `GLC` in stderr; writes `$T/clash/` with `a.pdb` and `a.cif` and asserts nonzero exit and that `$T/clash-out` holds no structure. Then `python3 -I check.py "$T"`. `check.py` asserts:
  - `relax.tsv` has two rows, header exact, every `energy_after < energy_before`, every `heavy_atom_rmsd < 0.5`.
  - In `relax/complex.cif`: residue names at the two Asn sites are `NLN`; the core's sugars, in chain order, are `4YB`, `4YB`, `VMB`, `0MA`, `0MA`; the lone site's sugar is `0YB`; every sugar residue has hydrogens; the total atom count equals the value pinned from the first passing run (write it in with a comment saying so).

### Task 5: `openmm md` with resuming

**Files:**
- Modify: `tools/openmm/bin/openmm`, `tools/openmm/test/run.sh`, `tools/openmm/test/check.py`

**Interfaces:**
- Consumes: `prepare`, `forcefield`, `select_platform` (Task 4).
- Produces: `openmm md <structure> <out> --ns FLOAT [--seed INT]`, writing `system.pdb`, `equilibrated.pdb`, `topology.pdb` (protein + glycans, the trajectory's atoms), `trajectory.dcd` (via `DCDReporter(..., atomSubset=...)`), `log.csv` (production only; equilibration reports to stderr), `final.pdb`, `state.xml` (atomic: write `state.xml.tmp`, `os.replace`), `input.sha256`. Production steps count from 0 at production start; frame k is at step 25,000·k.
- Resume rule: if `state.xml` exists — refuse (nonzero, nothing written) when `input.sha256` differs; else load the state, cut `trajectory.dcd` to `state_step / 25000` frames (header + n·frame bytes; update the header's frame count) and `log.csv` to rows with step ≤ the state's, and continue to `--ns`. If the state's step ≥ `--ns`'s, print a message to stderr and exit 0 touching nothing. No `state.xml` → start over from preparation.

- [ ] **Step 1: Write the failing test.** Append to `run.sh`: `openmm md "$T/relax/complex.cif" "$T/md" --ns 0.2` (GLYCAM-named input, the chaining path); then `openmm md ... --ns 0.4` (extend); then hash all files and `openmm md ... --ns 0.3` (smaller: unchanged); then append one extra frame to `trajectory.dcd` (OpenMM `DCDFile` with `append=True`, positions from `final.pdb`'s subset) and one extra row to `log.csv`, and rerun `--ns 0.5`; then `openmm md "$T/in/1UBQ.pdb" "$T/md" --ns 0.5` must exit nonzero. `check.py` asserts: the hashes before and after `--ns 0.3` match; `trajectory.dcd` holds exactly 5 frames; `log.csv`'s production steps are strictly increasing with no duplicates and end at 125,000; `topology.pdb`'s atom count equals the DCD's per-frame atom count and contains no `HOH`, `NA`, or `CL`; `system.pdb`'s box sides each ≥ 3 nm (cuPotential's 3×cutoff floor).
