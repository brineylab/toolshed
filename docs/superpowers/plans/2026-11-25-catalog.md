# CI-generated `CATALOG.md` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatically generate and maintain `CATALOG.md` at the repository root on `main` whenever tools, records, or the generator change, and point `README.md` and `AGENTS.md` at it.

**Architecture:** A stdlib Python script (`scripts/catalog.py`) reads `tools/*/SKILL.md` frontmatter (reusing `scripts/check.py:frontmatter`) and `results/<name>/<version>.txt`, rendering a flat alphabetical Markdown table with `Tool`, `Version`, `Tested on`, and full `Summary` columns. A dedicated workflow (`.github/workflows/catalog.yml`) runs on pushes to `main` touching `tools/**`, `results/**`, or `scripts/catalog.py` (plus `workflow_dispatch`), authenticating with a repo-scoped write deploy key (`CATALOG_DEPLOY_KEY`) listed in a `main` Repository Ruleset bypass list so `tools.yml` and `promote` stay untouched and forks without the secret skip pushing cleanly.

**Tech Stack:** Python 3.8+ stdlib (`python3 -I`, `unittest`), GitHub Actions (`actions/checkout@v7` with `ssh-key`), GitHub Repository Rulesets & Deploy Keys, `actionlint` (via podman if available).

**Spec:** `docs/superpowers/specs/2026-11-25-catalog-design.md`

## Global Constraints

- `scripts/catalog.py` runs under `python3 -I` on Python 3.8+, stdlib only, `from __future__ import annotations`, reusing `scripts/check.py:frontmatter`.
- Nothing in `scripts/` or `.github/` names the lab; forks work with zero edits and skip pushing cleanly when `CATALOG_DEPLOY_KEY` is unset.
- Do not edit `docs/VISION.md`, `docs/DESIGN.md`, or `.github/workflows/tools.yml`.
- All unit tests run via `python3 -I -m unittest discover tests`.
- Commit messages are one sentence stating the behavior.

## Review Focus

1. **Special characters in `SKILL.md` descriptions**: a `description` containing `|`, embedded newlines, or outer whitespace would break the Markdown table row; newlines must collapse to single spaces and `|` must be escaped as `\|`. Pinned in Task 1 (`test_escapes_pipes_and_collapses_whitespace`).
2. **Varied GPU/CPU output formats and missing records in `results/<name>/<version>.txt`**: records include column-0 `GPU 0: NVIDIA B200 (UUID: ...)`, timestamp-prefixed `[...] gpu-swann-0: GPU 0: NVIDIA L40S (UUID: ...)`, CPU `gpu: none`, CPU `No devices found.`, and potentially missing or unrecognized files; extraction must normalize GPU names, map both CPU markers to `CPU`, and fall back to `—` without crashing. Pinned in Task 1 (`test_tested_on_parses_gpu_cpu_and_fallbacks`).
3. **Non-tool entries under `tools/`**: stray files (e.g. `.DS_Store`) or directories without `SKILL.md` must be ignored rather than raising `FileNotFoundError` or `KeyError`. Pinned in Task 1 (`test_ignores_non_tool_entries_under_tools`).
4. **Determinism and real-repo coverage**: entries must sort alphabetically by directory name with a single trailing newline so CI's `git diff --quiet` never creates spurious commits, and running against the live repo must find every tool with a recognized `Tested on` value (no `—`). Pinned in Task 1 (`test_renders_sorted_deterministic_table_and_writes_output`, `test_real_repo_catalog_has_no_unknown_hardware`).
5. **Forks without `CATALOG_DEPLOY_KEY` and rapid back-to-back merges**: the workflow must skip committing/pushing without failing when the secret is empty, serialize concurrent runs (`cancel-in-progress: false`), rebase before pushing, and never trigger itself (its commit touches only `CATALOG.md`, outside its path filter). Verified in Task 2 (workflow YAML + lint) and Task 3 (live rollout).

### Task 1: Catalog generator (`scripts/catalog.py`) and unit tests (`tests/test_catalog.py`)

**Files:**
- Create: `scripts/catalog.py`
- Create: `tests/test_catalog.py`

**Interfaces:**
- Consumes: `check.frontmatter(path: Path) -> dict` from `scripts/check.py`.
- Produces, in `scripts/catalog.py`:
  - `tested_on(record: Path) -> str`: parses a test record (`results/<name>/<version>.txt`); returns the GPU model name matched by `r"GPU \d+: ([^(\n]+)"` stripped, `"CPU"` when `gpu: none` or `No devices found` appears in the body, or `"—"` when the file is missing or neither matches.
  - `collect(root: Path) -> list[dict[str, str]]`: scans `root / "tools"` in alphabetical order, skipping non-directories and directories without `SKILL.md`, returning dicts with keys `"name"`, `"version"`, `"tested_on"`, `"summary"`, `"skill"` (`"tools/<name>/SKILL.md"`).
  - `render(entries: list[dict[str, str]]) -> str`: renders the header (`# Toolshed Catalog` + one-line note pointing to each tool's `SKILL.md` for image URI, commands, compute, and gotchas) and Markdown table with columns `Tool`, `Version`, `Tested on`, `Summary`, escaping `|` as `\|` and collapsing whitespace/newlines in `Summary`, ending with a single `\n`.
  - CLI: `python3 -I scripts/catalog.py [--root DIR] [--output FILE]` (prints rendered catalog to stdout, or writes UTF-8 to `FILE` when `--output` is given).

- [ ] **Step 1: Create `.github/workflows/catalog.yml`**

Workflow requirements:
- `name: catalog` with a short header comment explaining it runs on hosted runners only, updates `CATALOG.md` on `main`, and skips push cleanly on forks without `CATALOG_DEPLOY_KEY`.
- Trigger:
  - `push:` on `branches: [main]` with `paths: ["tools/**", "results/**", "scripts/catalog.py"]`
  - `workflow_dispatch:`
- `permissions: { contents: read }` (actual push uses the repo deploy key, not `GITHUB_TOKEN`).
- `concurrency: { group: catalog, cancel-in-progress: false }` so rapid merges serialize instead of racing.
- Job `catalog` on `ubuntu-latest`:
  1. `actions/checkout@v7` with `ssh-key: ${{ secrets.CATALOG_DEPLOY_KEY }}` (falls back to HTTPS cleanly when the secret is empty on forks, pins GitHub's SSH host keys, and cleans up the key automatically).
  2. Run `python3 -I scripts/catalog.py --output CATALOG.md`.
  3. Commit and push step (with `env: HAS_DEPLOY_KEY: ${{ secrets.CATALOG_DEPLOY_KEY != '' }}`):
     - If `git diff --quiet -- CATALOG.md` and `CATALOG.md` is already tracked (`git ls-files --error-unmatch CATALOG.md >/dev/null 2>&1`), print `CATALOG.md is up to date` and exit 0.
     - If `[[ "$HAS_DEPLOY_KEY" != "true" ]]`, print `CATALOG_DEPLOY_KEY is not set; skipping push` and exit 0.
     - Configure git author (`github-actions[bot]` / `41898282+github-actions[bot]@users.noreply.github.com`), stage `CATALOG.md`, commit with `"Update CATALOG.md from tools and results"`, pull `--rebase origin main` (preserving the commit if `main` advanced), and `git push origin HEAD:main`.
